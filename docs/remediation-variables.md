# Remediation variables

Scope: every topic toggle and rule toggle of the collection. Audience: operators and
reviewers. Jira: FREES-55.

This page is generated by `make toggles` from the rule catalogue
[`roles/remediate/vars/rules.yml`](../roles/remediate/vars/rules.yml), together with the
toggle defaults in `defaults/main.yml` and their argument specifications in
`meta/argument_specs.yml` of both the `remediate` and the `audit` role, which carry the
same toggles. Do not edit any of them by hand: `make lint` fails when one differs from
the catalogue.

The toggles are flat booleans ([ADR 0011](adr/0011-control-toggles-and-cleanup.md)). A
family toggle defaults to `true` and a rule toggle to the value of its family toggle, so
setting `linux_compliance_<family>_enabled: false` once switches off every catalogued
rule of the topic, and a rule toggle set explicitly wins over its family toggle. The
remediate role cleans up a switched-off rule that it applied before, and the audit role
excludes it from the scan and reports it as `disabled`, naming the controlling variable.
How the toggles combine with the global opt-in and the disruptive allow-list is
described in [the remediation guide](remediation.md#effective-state-of-a-rule). Pass
them as JSON on the command line, for example `-e '{"linux_compliance_auditd_enabled":
false}'`.

## What a topic toggle covers

A topic toggle covers only the rules of its family that are in the rule catalogue below.
Profile rules of the same topic that the catalogue does not contain are still audited;
disable them with `linux_compliance_audit_disabled_rules`. When a topic toggle is
`false` but no catalogued rule of its family is selected by the profile, both roles
print a runtime warning that starts with `WARNING:` and says that the toggle currently
excludes nothing. Extending the catalogue to every profile rule is FREES-53.

## Controlling variable

When a rule is off, `disabled_by` names the family toggle whenever the family toggle is
`false`, and the rule toggle otherwise. If both are `false` and the family toggle is
later set back to `true`, the rule stays off and `disabled_by` changes to the rule
toggle.

Both roles define every toggle as a role default, so a value copied from a default into
the inventory, such as `linux_compliance_rule_<id>_enabled` set to `"{{
linux_compliance_<family>_enabled }}"` without the family toggle, resolves the same way
in both. A template that names a variable that is defined nowhere fails both roles
before anything is scanned or changed.
