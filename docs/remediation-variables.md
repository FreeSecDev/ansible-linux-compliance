# Remediation variables

Scope: every topic toggle and rule toggle of the collection. Audience: operators and
reviewers. Jira: FREES-55.

This page is generated by `make toggles` from the rule catalogue
[`roles/remediate/vars/rules.yml`](../roles/remediate/vars/rules.yml), together with the
toggle defaults in `roles/remediate/defaults/main.yml` and their argument specifications in
`roles/remediate/meta/argument_specs.yml`. Do not edit it by hand: `make lint` fails when any
of the three differs from the catalogue.

The toggles are flat booleans ([ADR 0011](adr/0011-control-toggles-and-cleanup.md)). A family
toggle defaults to `true` and a rule toggle to the value of its family toggle, so setting
`linux_compliance_<family>_enabled: false` once switches off the whole topic, and a rule
toggle set explicitly wins over its family toggle. The remediate role cleans up a
switched-off rule that it applied before, and the audit role excludes it from the scan and
reports it as `disabled`, naming the controlling variable. How the toggles combine with the
global opt-in and the disruptive allow-list is described in
[the remediation guide](remediation.md#effective-state-of-a-rule). Pass them as JSON on the
command line, for example `-e '{"linux_compliance_auditd_enabled": false}'`.
